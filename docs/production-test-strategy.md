# 生产测试策略

## 目标

本策略面向制度助手后端的生产化测试补强，先建立可运行、低依赖的测试骨架，再随着 RBAC、资产生命周期、异步任务和 AI 审计能力落地逐步转为行为测试。当前新增测试不依赖尚未实现的服务，不启动真实大模型，不要求外部知识库可用。

## 覆盖范围

1. RBAC：固定角色、权限点、最小权限矩阵，以及需要权限保护的高风险接口。
2. 资产状态机：固定制度/流程资产从草稿、送审、批准、发布到归档/驳回的生命周期契约。
3. 异步任务状态机：固定任务从排队、运行到成功/失败/取消的生命周期契约。
4. AI 调用审计：固定 LLM 调用前后、降级、失败和验证失败的审计事件名称及关键 payload 字段。
5. 端到端主链路：固定上传制度、保存资产、运行技能、生成发现、处理发现、导出结果和审计查询的接口契约。

## 分层策略

### L0 静态契约测试

已落地在 `backend/tests/production/`。这一层只做导入、路由注册、Literal 常量、测试侧契约和 hook 名称验证，适合在服务能力未完全实现时持续运行。

重点断言：

- `FindingStatus`、`VersionStatus`、`SkillRunResult.status`、`RoleMapping.status` 不发生无意漂移。
- 主链路 API 路由已注册。
- RBAC 矩阵、状态机、AI 审计事件契约自身是良构的。
- 尚未实现的 RBAC 依赖、异步任务接口、显式资产生命周期接口以 `xfail` 形式占位。

### L1 单元测试

RBAC、状态机、审计记录器实现后，应补充纯函数级测试：

- RBAC：角色继承、权限拒绝、越权访问、审计日志补充。
- 资产状态机：合法迁移、非法跳转、终态不可变、驳回后回草稿。
- 异步任务状态机：任务幂等、取消竞态、失败重试边界。
- AI 审计：prompt 摘要、模型名、调用耗时、token/费用、错误原因、关联 skill_run_id。

### L2 接口测试

接口实现稳定后，将 `xfail` 占位测试转为真实 FastAPI TestClient 测试：

- 匿名访问高风险接口返回 401。
- 无权限角色访问返回 403。
- 有权限角色访问成功且产生审计记录。
- 资产生命周期接口返回新状态和操作者信息。
- 异步任务查询接口可观察 queued/running/succeeded/failed/cancelled。

### L3 端到端主链路

主链路测试建议使用 mock LLM 和内存/临时数据库：

1. 上传制度源文件并分析。
2. 保存为新制度或新版本。
3. 运行制度-流程一致性 Skill。
4. 生成发现并完成二次证据验证。
5. 关闭或驳回发现。
6. 导出发现 Excel。
7. 查询 AI 调用审计和 hook 事件，确认每个关键动作可追溯。

预期结果：已实现契约测试通过，未实现能力对应测试显示为 `xfailed`。当相关服务实现后，应先删除对应 `xfail`，再补充真实行为断言。

## 后续转正标准

- RBAC：所有写接口、审计接口、删除/归档接口都有统一权限依赖。
- 资产状态机：业务代码暴露明确状态字段和迁移函数，不允许接口直接写任意状态。
- 异步任务：任务 ID、状态、错误、结果摘要、创建/更新时间可查询。
- AI 审计：每次真实或 mock LLM 调用都有成对审计事件，并能关联到技能运行、资产、发现和操作者。
- 主链路：完整测试不依赖外部网络，失败时能指出断裂环节。
